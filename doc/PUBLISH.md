## 短版（适合社交平台 / 群聊转发）

> **LX Focus** —— 一个会拦截分心的专注工具。
>
> 设好时长与目标，开始专注。应用进入全屏独占、屏幕级置顶，拦截 Win 键与 Alt+Tab；被调到前台的其他窗口会自动最小化。
>
> 专注期间自动播放指定的歌单，休息时切换到另一套或静音。
>
> 没有打卡按钮，也无法手动补记——会话如实落盘，中途分心次数一并记录。
>
> 基于 LX Music 二次开发，Apache-2.0。Windows 10 / 11，提供安装版与绿色版。

## 标准版（适合 README 摘要 / 作品集 / 博客）

### 为什么做这个

常见的番茄钟本质上是一个计时器：它提醒你专注，但约束不了你的手。

真正让专注失败的往往不是「忘了计时」，而是那一瞬间——手比脑子快，Alt+Tab 已经按下去了。

LX Focus 要处理的就是这一瞬间：**把分心的摩擦成本抬高**。

它不是要造一个不可破解的笼子，而是留下几秒钟的阻力，让人来得及想一下「我真的要切走吗」。

### 它做什么

> 【配图】专注界面待机态 —— 圆环、阶段 pill、右侧目标设置

**专注界面**

环形计时器，预设 15 / 25 / 45 / 60 / 90 分钟也可以手填；支持多轮循环（专注 → 休息 → 专注）；7 天专注时长柱状图、今日汇总、最近会话列表。

**四层专注锁**，逐层增强，越往下对系统侵入越深：

| 层 | 手段 |
|---|---|
| 窗口层 | kiosk 全屏独占、屏幕级置顶、失焦自动夺回 |
| 快捷键层 | 屏蔽 Alt+F4 / Ctrl+W / F11 / Ctrl+Shift+I |
| 进程层 | 低级键盘钩子吞掉 Win 键与 Alt+Tab；前台窗口看门狗 |
| 意志层 | 暂停 / 结束需要解锁码 |

**音乐联动**

专注期间和休息期间分别指定歌单，也可以设置休息时静音。

> 【配图】专注中 —— 与上一张对比：光晕亮起、进度弧着色、防护状态转入「完整防护」

**它承认自己做不到的事**

`Ctrl+Alt+Del` 由内核接管，任何用户态程序都无法拦截；任务管理器的强制结束是系统保留的通道。

这些并未被隐藏，而是与「已生效」的项目并列显示在防护状态中。**自律工具若声称封锁了一切，比它承认存在边界更危险。**

### 数据

会话记录只存在本机，不联网、不上传。

解锁码只做本地散列比对——它是一道「自我承诺」的缓冲，不是安全边界。忘记解锁码时，改配置文件即可重置。这是刻意保留的出口：**自律工具不应让使用者把自己锁死在软件里。**

## 长版（适合发帖 / 独立文章）

### 一、为什么不是又一个番茄钟

常见的番茄钟有一个共同点：**它们本质上都只是计时器。**

倒计时在走，人在做别的事。等提示音响起，点一下确认，然后继续。

问题在于，分心通常并不发生在「决定」这一步。它是肌肉记忆——按下 Alt+Tab 时人甚至没有意识到，反应过来时已经在浏览器里了。

所以要拦截的不是意志，是那半秒钟。

LX Focus 的做法是：全屏独占、屏幕级置顶、失焦自动夺回、屏蔽常用退出快捷键，再由一个原生辅助进程通过低级键盘钩子拦截 Win 键与 Alt+Tab，配合前台窗口看门狗——只要当前前台不是本应用，就将其最小化。

即便如此，仍然可以切走（原因见下一节）。但中间多了几秒的阻力。**几秒钟，足够让人想起自己原本在做什么。**

### 二、关于「锁」这件事的取舍

设计时反复权衡的一个问题是：要锁到什么程度？

结论是不锁死。理由有三层：

**技术上锁不死。** `Ctrl+Alt+Del` 是 Windows 的安全注意序列，由内核接管，任何用户态程序都无法拦截。任务管理器的强制结束是系统保留的通道。安全模式更是绕过一切。这些都是设计使然，不是实现缺陷。

**锁死了会带来实际问题。** 一个无法暂停的应用，遇到需要立刻处理的事情时怎么办？线上会议、有人来找、临时想起的待办——如果唯一出路是强制结束进程，这个工具就变成了负担。

**锁死了也没有意义。** 自律工具的全部价值，建立在「使用者愿意遵守」之上。如果确实决心要逃，没有任何软件拦得住——拔电源即可。既然如此，与其声称封锁一切，不如**如实说明边界**。

所以专注界面里，「已生效」的 8 项与「无法防护」的 3 项是并列显示的。使用者需要清楚知道自己在依赖什么，以及这道防线在哪里会断。

解锁码的设计同理：它只做本地散列比对，忘记后可以直接改配置重置。它的作用是「让暂停这个动作不那么顺手」，而不是「让暂停变得不可能」。

> 把分心的摩擦成本抬高，而不是造一个不可破解的笼子。


### 三、界面

> 【配图】待机态 + 专注中，两张并排

计时器是这个应用的主角，所以核心是一个 320px 的圆环。它由三层叠成：底部的轨道、专注时会缓慢呼吸的光晕、以及随阶段变色的进度弧。

配色随阶段切换——专注是绿，暂停是橙，休息是青。上方一枚 pill 标签显示当前阶段与轮次（如「专注中 · 第 2 轮」），底部一排圆点表示总轮次与进度。

配色全部走主题变量，浅色和深色主题都完整适配过，没有任何硬编码色值。系统开了「减弱动效」时会关掉全部动画。

### 四、实现上的几个决定

**与上游脱钩。** `appId` 和 `productName` 都改了。沿用上游的 appId 会让两个应用共用同一份用户数据目录、互相覆盖配置——这是个安静但很烦人的 bug。

**打包不需要 Visual Studio。** 依赖的三个原生模块（`better-sqlite3`、`bufferutil`、`utf-8-validate`）全部是 N-API 模块并自带预编译件，ABI 在 Node 与 Electron 之间稳定。所以关掉了 electron-builder 默认的 `npmRebuild`，把「本机装有 C++ 生成工具」这个前置条件整个去掉了。

**原生辅助进程用系统自带的 `csc.exe` 编译。** 不引入 .NET SDK 依赖。非 Windows 平台会自动跳过，专注锁降级为窗口层 + 快捷键层。

**移除了自动更新。** 上游在源码里铺了多个指向自身的版本信息端点和更新弹窗。fork 若原样沿用，使用者会被提示「有新版本」并被引导下载**上游的**安装包。与其把这些链接逐个改写，不如整条链路删掉——新版本手动下载覆盖安装即可。

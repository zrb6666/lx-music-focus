## 标准版（适合 README 摘要 / 作品集 / 博客）

### 为什么做这个

市面上的番茄钟大多是个计时器：它提醒你专注，但管不住你的手。

真正让专注失败的往往不是「忘了计时」，而是那一瞬间——手比脑子快，Alt+Tab 已经按下去了。

LX Focus 想解决的就是这一瞬间：**把分心的摩擦成本抬高**。

不是造一个不可破解的笼子。是有那么几秒钟的阻力，让你来得及想一下「我真的要切走吗」。

### 它做什么

> 【配图】专注界面待机态 —— 圆环、阶段 pill、右侧目标设置

**专注界面**

环形计时器，预设 15 / 25 / 45 / 60 / 90 分钟也可以手填；支持多轮循环（专注 → 休息 → 专注）；7 天专注时长柱状图、今日汇总、最近会话列表。

**四层专注锁**，逐层增强，越往下对系统侵入越深：

| 层 | 手段 |
|---|---|
| 窗口层 | kiosk 全屏独占、屏幕级置顶、失焦自动夺回 |
| 快捷键层 | 屏蔽 Alt+F4 / Ctrl+W / F11 / Ctrl+Shift+I |
| 进程层 | 低级键盘钩子吞掉 Win 键与 Alt+Tab；前台窗口看门狗 |
| 意志层 | 暂停 / 结束需要解锁码 |

**音乐联动**

专注期间和休息期间分别指定歌单，也可以设置休息时静音。

> 【配图】专注中 —— 与上一张对比：光晕亮起、进度弧着色、防护状态转入「完整防护」

**它承认自己做不到的事**

`Ctrl+Alt+Del` 由内核接管，任何用户态程序都拦不住；任务管理器的强制结束是系统保留的逃生通道。

这些没有被藏起来，而是和「已生效」的项目并列显示在防护状态里。**一个自律工具假装自己封死了一切，比它承认有边界更危险。**

### 数据

会话记录只存在本机，不联网、不上传。

解锁码只做本地散列比对——它是一道「自我承诺」的缓冲，不是安全边界。忘记了解锁码，改配置文件即可重置。这是刻意留的出口：**任何自律工具都不该让使用者把自己锁死在软件里。**

## 长版（适合发帖 / 独立文章）

### 一、为什么不是又一个番茄钟

我用过不少番茄钟。它们的问题惊人地一致：**它们都只是计时器。**

倒计时在跑，你在刷别的。等它响了，你点一下「知道了」，然后继续。

后来我意识到，分心这件事根本不发生在「决定」层面。它是肌肉记忆——你甚至没意识到自己按了 Alt+Tab，人已经在浏览器里了。

所以要拦的不是你的意志，是那半秒钟。

LX Focus 的做法很直接：全屏独占、屏幕级置顶、失焦自动夺回、屏蔽常用退出快捷键，再由一个原生辅助进程用低级键盘钩子把 Win 键和 Alt+Tab 吞掉，加上前台窗口看门狗——只要不是本应用在前台，就把它最小化。

这一套下来，你还是能切走（我下面会说为什么必须能）。但中间多了几秒的阻力。**几秒钟，够你想起自己在干什么了。**

### 二、关于「锁」这件事的取舍

设计过程中我反复问自己一个问题：要锁多死？

答案是不锁死。理由有三层：

**技术上锁不死。** `Ctrl+Alt+Del` 是 Windows 的安全注意序列，由内核接管，任何用户态程序都拦不住。任务管理器的强制结束是系统保留的逃生通道。安全模式更是绕过一切。这些都是设计使然，不是实现缺陷。

**锁死了会出事。** 一个不能暂停的应用，遇到急事怎么办？线上会议、家人敲门、突然想起的待办——如果唯一的出路是强制结束进程，那这个工具就变成了负担。

**锁死了没有意义。** 一个自律工具的全部价值，建立在「你愿意遵守」这件事上。如果你真的铁了心要逃，没有任何软件拦得住你——拔电源就行了。既然如此，与其假装封死一切，不如**如实告知边界**。

所以专注界面里，「已生效」的 8 项和「无法防护」的 3 项是并列显示的。我希望使用者清楚地知道自己在依赖什么、以及这道防线在哪里会断。

解锁码的设计也是同一个思路：它只做本地散列比对，忘记了大可以改配置文件重置。它存在的意义是「让暂停这个动作不那么顺手」，而不是「让暂停变成不可能」。

> 把分心的摩擦成本抬高，而不是造一个不可破解的笼子。

### 三、界面

> 【配图】待机态 + 专注中，两张并排

计时器是这个应用的主角，所以核心是一个 320px 的圆环。它由三层叠成：底部的轨道、专注时会缓慢呼吸的光晕、以及随阶段变色的进度弧。

配色随阶段切换——专注是绿，暂停是橙，休息是青。上方一枚 pill 标签告诉你现在是「专注中 · 第 2 轮」，底部一排圆点表示总轮次和进度。

配色全部走主题变量，浅色和深色主题都完整适配过，没有任何硬编码色值。系统开了「减弱动效」时会关掉全部动画。

### 四、实现上的几个决定

**与上游脱钩。** `appId` 和 `productName` 都改了。沿用上游的 appId 会让两个应用共用同一份用户数据目录、互相覆盖配置——这是个安静但很烦人的 bug。

**打包不需要 Visual Studio。** 依赖的三个原生模块（`better-sqlite3`、`bufferutil`、`utf-8-validate`）全部是 N-API 模块并自带预编译件，ABI 在 Node 与 Electron 之间稳定。所以关掉了 electron-builder 默认的 `npmRebuild`，把「本机装有 C++ 生成工具」这个前置条件整个去掉了。

**原生辅助进程用系统自带的 `csc.exe` 编译。** 不引入 .NET SDK 依赖。非 Windows 平台会自动跳过，专注锁降级为窗口层 + 快捷键层。

**移除了自动更新。** 上游在源码里铺了多个指向自身的版本信息端点和更新弹窗。fork 若原样沿用，使用者会被提示「有新版本」并被引导下载**上游的**安装包。与其把这些链接逐个改写，不如整条链路删掉——新版本手动下载覆盖安装即可。
